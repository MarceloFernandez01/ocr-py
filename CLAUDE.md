# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Alcance del proyecto

MVP de un aplicativo de escritorio en Python para OCR (Optical Character Recognition): transcribe imágenes a texto en español e inglés, reconociendo la mayor cantidad de fuentes posible.

Restricciones del proyecto y decisiones técnicas cerradas en `specs/01-mvp-ocr-tesseract-tkinter.md`:

- **Evitar módulos externos salvo que sea estrictamente necesario.** Las dependencias externas aprobadas son `pytesseract` (motor OCR), `Pillow` (decodificación de imágenes en cualquier formato para la vista previa en GUI), `numpy` y `opencv-python` (preprocesamiento de imagen para OCR sobre fondos complejos, ver `specs/03-preprocesamiento-ocr.md`), `PySide6` (toolkit de GUI, ver `specs/04-migracion-pyside6-menu-inicio.md`), `argostranslate` (traducción offline del texto reconocido en OCR en vivo, ver `specs/11-traduccion-ocr-en-vivo.md`), `anthropic` (SDK oficial de Anthropic, motor OCR alternativo vía Claude Haiku 4.5, ver `specs/13-ocr-claude-motor-alternativo.md`) y `keyring` (almacenamiento seguro de la API key de Anthropic en el keyring del SO, ver `specs/13-ocr-claude-motor-alternativo.md`). No agregar otras sin pasar antes por una spec.
- **Respetar el patrón MVC** (Modelo-Vista-Controlador) en la organización del código: `model/` (lógica de OCR y config, sin importar PySide6), `view/` (ventana y widgets PySide6, sin llamar a `pytesseract` directamente), `controller/` (conecta eventos de la vista con el modelo).
- **GUI en PySide6 con skin visual estilo Metro** (tipografía Segoe UI, superficies planas, tiles, acento azul), centralizado en `view/metro_style.py` (ver `specs/06-reskin-metro.md`). Soporta tema oscuro y claro con toggle en caliente desde la vista de Configuración (ver `specs/07-menu-configuracion-sidebar.md`); default oscuro, persistido en `config.json`.
- **Motor OCR: Tesseract vía `pytesseract`.** El usuario debe instalar Tesseract-OCR manualmente en el sistema (no se instala vía pip ni se instala automáticamente desde la app). La app detecta la ruta por PATH; si no la encuentra, pide la ruta manualmente y la persiste en `config.json`.
- **Selector de idioma con 3 opciones fijas:** Español (`spa`), Inglés (`eng`), Ambos (`spa+eng`). Idiomas adicionales quedan para specs futuras.
- **Fuera de alcance del MVP:** guardado del texto a archivo o historial entre sesiones, instalación automática de Tesseract, motor ICR. (OCR en vivo/captura de pantalla ya está implementado, ver specs 08-10.)
- **El código debe estar documentado.** Cada módulo, clase y función pública lleva un docstring explicando su propósito (qué hace, parámetros y valor de retorno cuando no sean obvios). Esto tiene prioridad sobre la preferencia global de evitar comentarios/documentación innecesaria.
- **La IA no puede cambiar ni implementar nuevas funcionalidades si no se pide explisitamente.**  Solamente podra ser sugerencias, las cuales el usuario puede aprobar o rechazar.

El MVP descrito en `specs/01-mvp-ocr-tesseract-tkinter.md` ya está implementado. Estructura actual del código (detalle de cada módulo en su propio docstring):

- `main.py` — entry point, arranca `QApplication` + `MainWindow`.
- `model/config_model.py` — carga/guarda `config.json` (`theme`, `engine`, `translation_engine`, `plugins`, ...); también define `KEYRING_SERVICE`/`KEYRING_USERNAME` (este último solo como referencia para la migración de la API key legacy de Claude, spec 18/19). `plugin_keyring_username(plugin_id, field_key)` arma el username nuevo por plugin en el keyring; `save_plugin_setting_field(plugin_id, key, value)` persiste un solo campo dentro de `plugins.<id>.settings`. `load_config()` migra automáticamente la clave legacy top-level `tesseract_path` (si existe) a `plugins.tesseract.settings.tesseract_path` (spec 19).
- `model/tesseract_locator.py` — resuelve la ruta de Tesseract (PATH, Tesseract embebido si la app corre congelada, o `plugins.tesseract.settings.tesseract_path` de `config.json`, spec 19).
- `model/ocr_model.py` — wrapper de `pytesseract`, orquesta tiling y preprocesamiento; `transcribe_image_variants` acepta un parámetro opcional `variants` (variantes ya calculadas por el llamador, usado por `plugins_core/tesseract/`; con `None` las genera internamente, sin regresión, spec 18).
- `model/image_tiling.py` — tiling/downscale de imágenes grandes (spec 02).
- `model/image_preprocessing.py` — variantes de preprocesamiento y upscaling con selección por confianza (spec 03).
- `model/image_diff.py` — compara capturas de pantalla para detectar cambios significativos, usado en el polling de OCR en vivo (spec 08).
- `model/translation_model.py` — traducción offline del texto reconocido vía `argostranslate`, con descarga on-demand del modelo de idioma (spec 11).
- `model/claude_ocr_model.py` — OCR alternativo vía Claude Haiku 4.5 (SDK `anthropic`), con import perezoso del SDK; redimensiona la imagen solo si excede los límites de tamaño de la API (spec 13); `transcribe_image_claude` devuelve `(texto, input_tokens, output_tokens)` para el cálculo de costo (spec 16).
- `model/text_diff.py` — compara dos transcripciones por umbral de similitud (`difflib.SequenceMatcher`, biblioteca estándar) para detectar cambio real de texto entre capturas en OCR en vivo, filtrando jitter/ruido visual (spec 16).
- `model/claude_usage_model.py` — costo por llamada a Claude Haiku 4.5 a partir de los tokens reales de la API y acumulación del gasto mensual en `config.json` (spec 16).
- `model/hotkey_model.py` — traducción y validación de combinaciones de teclas en notación `QKeySequence` a los códigos que espera `RegisterHotKey` de Windows (`has_modifier`, `parse_virtual_key`); no importa PySide6 ni `ctypes` (spec 17).
- `model/plugin_manifest.py` — parseo y validación del manifiesto `plugin.json` de un plugin (`PluginManifest`, `parse_manifest`, `PLUGIN_API_VERSION` = `2`, `CAPABILITIES`); el manifiesto puede declarar `settings` (lista de `SettingField`: `key`, `label`, `type` uno de `SETTING_FIELD_TYPES` = `("text", "number", "boolean", "api_key")`, `required`, `default`), unificando ajustes y prerrequisitos en un solo esquema (spec 19); sin PySide6, sin importar el módulo del plugin (spec 18).
- `model/plugin_registry.py` — descubrimiento, importación aislada (`importlib.util.spec_from_file_location`) y despacho por capacidad de los plugins de `plugins_core/` y `plugins/`: `load_plugins`/`get_plugins`/`reload_plugins`, `list_providers`/`get_provider`, `can_disable` (protege a un esencial mientras sea el proveedor seleccionado en `config.json`), `missing_essentials`, `set_enabled` (activa/desactiva sin reimportar módulos, spec 19), `PluginContext` (única superficie que un plugin recibe de la app, incluye `preprocess()`), `PluginError` (envuelve la excepción de un plugin nombrándolo) y `run_ocr`/`run_translation`; `LoadedPlugin` incluye `description` y `settings: list[SettingField]` (spec 19). `resolve_setting_value`/`save_setting_value` (spec 19) resuelven y persisten un campo de ajuste: `api_key` va al keyring bajo `plugin_keyring_username(plugin_id, field_key)` (con migración automática, solo para `claude:api_key`, desde el username legacy `KEYRING_USERNAME` en el primer acceso); el resto usa `config["plugins"][id]["settings"]` con el `default` del manifiesto como respaldo. `missing_required_settings(plugin_id)` devuelve los `SettingField` obligatorios sin valor; `run_ocr`/`run_translation` arman el `settings` que reciben los plugins resolviendo cada campo declarado. Sin PySide6 (spec 18).
- `view/main_window.py` — `MainWindow`, sidebar + `QStackedWidget` con 4 vistas (`OcrView`, `LiveOcrView`, `SettingsView`, `PluginsView`) y una barra de gasto de Claude (`SpendMeterView`) debajo, visible solo con motor Claude y API key guardada; `apply_theme(theme)` para tema en caliente y `refresh_spend_meter()` para refrescar/ajustar el alto fijo de la ventana según esa barra (spec 16); navegar a "Plugins" no detiene OCR en vivo, a diferencia de "OCR de imágenes" y "Configuración" (spec 19).
- `view/sidebar_view.py` — panel lateral persistente ("OCR de imágenes", "OCR en vivo", engranaje Configuración, botón de plugins 🧩), señales `ocr_selected`/`live_ocr_selected`/`settings_selected`/`plugins_selected` (spec 19).
- `view/ocr_view.py` — flujo de OCR sobre imágenes (abrir, idioma, recorte/zoom/paneo sobre la preview, transcribir, resultado); no conoce motores concretos, `OcrController` despacha al plugin de OCR seleccionado en Configuración (specs 10, 12, 13, 18).
- `view/live_ocr_view.py` — pantalla de OCR en vivo: activa el overlay de captura y controla el inicio/fin de la transcripción por polling (specs 08-09); indicador de estado (`status_label`/`set_status`) con los mismos cuatro rótulos que el overlay (spec 17).
- `view/screen_overlay.py` — overlay flotante para seleccionar el segmento de pantalla a capturar en OCR en vivo; la zona de agarre de las esquinas es invisible (solo cambia el cursor, sin dibujo de handles) para que `capture_geometry()` nunca incluya esos píxeles en el OCR; barra de control con indicador de estado, y botones de 32×32 px (traducir/pausar-reanudar/cerrar) con tooltips que interpolan el atajo global configurado (spec 17).
- `view/settings_view.py` — vista de Configuración: `ThemeSwitch` (tema claro/oscuro en caliente; reutilizado también por `PluginsView` para el interruptor de activar/desactivar y los campos `boolean` del acordeón, spec 19), combo de motor OCR y combo de motor de traducción alimentados dinámicamente desde `model/plugin_registry.list_providers` (nombre del manifiesto visible, id del plugin como `itemData`, spec 18); `refresh_engine_combos()` los repuebla preservando la selección vigente, usado por `PluginsController` tras "Recargar plugins" (spec 19). Campo de API key enmascarado guardado en el keyring del SO cuando el motor OCR es `claude`, aviso de costo del motor Claude (spec 13), deslizadores de sensibilidad al cambio de texto/imagen en OCR en vivo (siempre visibles) e interruptor + cooldown + presupuesto mensual exclusivos del motor Claude (spec 16), y dos `QKeySequenceEdit` para los atajos globales de OCR en vivo con aviso de validación/registro fallido (spec 17).
- `view/spend_meter_view.py` — `SpendMeterView`, franja horizontal con el progreso de gasto de Claude del mes en curso (llamadas, monto, presupuesto) y estado de alerta visual; solo presentación, sin lógica de negocio (spec 16).
- `view/plugins_view.py` — `PluginsView`: lista de plugins encontrados (nombre, versión, descripción, capacidades, estado con el mensaje de `LoadedPlugin.error` si aplica), badge "Esencial" sin interruptor para los tres nativos, interruptor de activar/desactivar (`ThemeSwitch`) para los demás, banner persistente cuando `missing_essentials()` no está vacío, botón "Recargar plugins", y un acordeón inline por plugin con sus campos de `settings` (`text`/`number`/`boolean`/`api_key`, persistidos al cambiar de valor). Señales `reload_requested`, `plugin_enabled_toggled(str, bool)`, `plugin_setting_changed(str, str, object)`; sin lógica de negocio (spec 19).
- `view/metro_style.py` — única fuente del QSS estilo Metro (`get_stylesheet(theme)`), sin lógica de negocio.
- `view/assets/` — íconos de chevron para `QComboBox`, uno por tema.
- `controller/common.py` — utilidades compartidas entre `OcrController` y `LiveOcrController`: mapa de idiomas, label de progreso, y `prompt_missing_settings(parent, plugin_id)` — pide por diálogo genérico (`QInputDialog.getText`, oculto para campos `api_key`) cada ajuste obligatorio faltante de `plugin_id` (`missing_required_settings`) y lo persiste (`save_setting_value`); reemplaza los chequeos hardcodeados por id de Tesseract/Claude que existían hasta spec 18 (spec 19).
- `controller/ocr_controller.py` — conecta `OcrView` con el Model: errores vía `QMessageBox`/`QFileDialog`, threading (`QThreadPool`/`QRunnable`) con contador de segundos, estado de recorte `_crop_box` (mapea preview→imagen original antes de transcribir) y despacho por `model/plugin_registry.run_ocr(plugin_id, ...)` sin conocer motores concretos; antes de transcribir, resuelve los ajustes obligatorios faltantes del plugin de OCR seleccionado vía `prompt_missing_settings` (genérico por manifiesto, ya no hardcodeado por id, spec 19), y refresca la barra de gasto de `MainWindow` tras cada transcripción exitosa, sin condicionar por motor (spec 18).
- `controller/live_ocr_controller.py` — ciclo de OCR en vivo: captura de pantalla, diff de píxeles (`image_diff`) y transcripción con el plugin `"tesseract"` como detector de cambio de texto (`run_ocr("tesseract", ...)`, `text_diff.has_text_changed`) antes de refrescar la vista o re-disparar traducción; si ese plugin no está disponible, degrada al diff de píxeles como único disparador y avisa una vez por activación en vez de cortar el ciclo (spec 18). Antes de arrancar el polling, resuelve los ajustes obligatorios faltantes de `"tesseract"` (siempre, es el detector) y de `"claude"` (solo si el ciclo en vivo lo usa) vía `prompt_missing_settings` (spec 19). Con motor Claude y el interruptor `live_claude_enabled` activado, un cambio de texto real dispara el plugin `"claude"` (`run_ocr("claude", ...)`, respetando un cooldown configurable con cola de la captura más reciente) y el panel solo muestra resultados de Claude, nunca del detector (spec 16); la traducción despacha por `run_translation(translation_engine, ...)` (spec 18). Propaga un estado (Detenido/Transcribiendo/Analizando…/Pausado) a la vista y al overlay en cada transición, sincroniza el botón de traducción de ambos, e instancia un `GlobalHotkeyManager` con vida igual a la de la app para pausar/reanudar y cerrar el overlay con atajos globales de Windows, con o sin foco en la aplicación; expone `register_hotkey()` para que `SettingsController` reintente un atajo nuevo (spec 17).
- `controller/global_hotkeys.py` — `GlobalHotkeyManager`, registro de atajos globales de Windows vía `RegisterHotKey`/`UnregisterHotKey` de `user32.dll` (`ctypes`) y un `QAbstractNativeEventFilter` sobre `QApplication` para capturar `WM_HOTKEY` y emitir `triggered(hotkey_id)`; `register()` prueba la combinación nueva bajo un id temporal antes de tocar el registro vigente, de forma que si Windows la rechaza (combinación ya tomada por otra aplicación) la combinación anterior sigue activa; en un SO distinto de Windows, `register()` devuelve `False` sin importar `ctypes.windll` (spec 17).
- `controller/settings_controller.py` — conecta el toggle de tema, el selector de motor OCR, el selector de motor de traducción (`save_translation_engine`) y los controles de OCR en vivo (interruptor de Claude, sensibilidad de texto/píxeles, cooldown, presupuesto mensual) de `SettingsView` con el model (`save_theme()`, `config.json`, keyring) y con `MainWindow.apply_theme()`/`refresh_spend_meter()`; la validación de API key sigue atada al id `"claude"` (spec 18; no generalizada por spec 19, que solo genericiza los chequeos de `OcrController`/`LiveOcrController` antes de transcribir). Valida los atajos globales nuevos (`has_modifier`) y los reintenta registrar vía `LiveOcrController.register_hotkey()` antes de persistirlos; si la validación o el registro fallan, revierte el campo y muestra el aviso, sin persistir el cambio (spec 17).
- `controller/plugins_controller.py` — `PluginsController` conecta `PluginsView` con `model/plugin_registry.py`: puebla la vista (con cada `SettingField.default` reemplazado por su valor vigente vía `resolve_setting_value`, para que el acordeón muestre el valor persistido) al mostrarse la vista (`plugins_selected` del sidebar) o tras recargar; `reload_requested` → `reload_plugins()` + repuebla + `SettingsView.refresh_engine_combos()`, deshabilitado mientras `main_window.ocr_controller.state.transcription_in_progress` o `main_window.live_ocr_controller._status != "Detenido"`; `plugin_enabled_toggled` → `set_enabled()`; `plugin_setting_changed` → `save_setting_value()` sin repoblar la vista (spec 19).
- `plugins_core/` — los tres plugins esenciales (Tesseract, Claude Haiku, Argos Translate), convertidos en plugins reales con el mismo contrato y manifiesto que uno de terceros: `plugins_core/tesseract/`, `plugins_core/claude/`, `plugins_core/argos/`, envoltorios finos sobre el código de `model/` correspondiente (que no se mueve ni se reescribe); manifiestos en `api_version: 2` con su esquema `settings` (`tesseract_path`/`api_key` obligatorios; Argos sin campos, spec 19). Se distribuye con la app; ésta no ofrece borrarlos y `can_disable` los protege mientras sean el proveedor seleccionado (spec 18).
- `plugins/` — carpeta para plugins de terceros (motor OCR, traductor o preprocesador) descubierta al arrancar; nunca se mezcla con `plugins_core/`. `plugins/README.md` documenta el contrato de las tres capacidades, el manifiesto, los ajustes en `config.json` y el aviso de seguridad (spec 18).
- `requirements.txt` — `pytesseract`, `Pillow`, `numpy`, `opencv-python`, `PySide6`, `argostranslate`, `anthropic`, `keyring`.
- `config.json` — generado en runtime (no versionado, `.gitignore`), incluye `theme`, `engine` (id del plugin de OCR activo), `translation_engine` (id del plugin de traducción activo, default `"argos"`, spec 18), `min_word_confidence`, `live_claude_enabled`, `text_similarity_threshold`, `pixel_change_sensitivity`, `claude_cooldown_seconds`, `claude_monthly_budget_usd`, `claude_spend` (acumulador mensual `{month, usd, calls}`), `hotkey_toggle` y `hotkey_close` (combinaciones en notación `QKeySequence` para los atajos globales de OCR en vivo, default `"Ctrl+Shift+P"`/`"Ctrl+Shift+Q"`), y `plugins` (diccionario por id de plugin con `enabled` y `settings` —ajustes declarados en su manifiesto, ej. `plugins.tesseract.settings.tesseract_path`—, default `{}` si el id no figura, spec 18). La ruta de Tesseract ya no vive en una clave top-level: `load_config()` migra automáticamente `tesseract_path` (formato de versiones anteriores) a `plugins.tesseract.settings.tesseract_path` la primera vez que arranca la app (spec 19). Los campos `api_key` (ej. la API key de Anthropic) no se guardan acá: van al keyring del SO bajo el username `"<plugin_id>:<field_key>"` (`plugin_keyring_username`); la API key de Claude guardada bajo el username legacy `anthropic_api_key` se migra automáticamente a `"claude:api_key"` en el primer acceso (spec 19).
- `docs/fixes-ocr.md` — changelog acumulativo de correcciones menores al motor Tesseract (sin trade-off para el usuario, sin spec propia), generado por la skill `/tesseract-bug`.

No hay comandos de build/lint/test configurados en el repo (no hay `pyproject.toml` ni `Makefile`). Para correr la app: `python main.py`. Antes de asumir que existe un comando de test o lint, verificar con `ls`.

## Flujo de trabajo: specs

Este repositorio usa el flujo de trabajo basado en specs (skills `spec` y `spec-impl`, instaladas vía `.agents/skills/`, catálogo `Klerith/fernando-skills`):

- `/spec <descripción>` — diseña una spec nueva sección por sección, haciendo preguntas de clarificación antes de proponer estructura. Guarda el resultado en `specs/NN-slug.md` con estado `Draft`.
- `/spec-impl <NN-slug>` — implementa una spec ya marcada como `Approved` por el usuario. Crea (o reutiliza) una rama `spec-NN-slug`, muestra el resumen de la spec y avanza paso a paso, pausando después de cada paso del plan de implementación para revisión de diff.
- `/tesseract-bug <descripción>` — skill de proyecto (`.claude/skills/tesseract-bug/`) para reportar fallos de reconocimiento del motor Tesseract, con imagen adjunta o ruta cuando sea posible. Diagnostica contra el pipeline real (`model/ocr_model.py`, `model/image_preprocessing.py`, `model/image_tiling.py`) y decide por el trade-off del arreglo: si nadie pierde nada, aplica un fix acotado en una rama `fix-ocr-<slug>` y lo documenta en `docs/fixes-ocr.md`; si el arreglo sacrifica otro caso de uso, redacta ella misma una spec nueva sección por sección (mismo método que `/spec`) en `specs/NN-slug.md` con estado `Draft`. Solo cubre el motor Tesseract, nunca edita en `master`/`main`, y nunca hace commit/merge/push.

Reglas clave de este flujo:

- Nunca se escribe código durante `/spec` — esa skill solo produce el archivo `.md` de la spec.
- `/spec-impl` se niega a avanzar si el estado de la spec no significa "Approved" (en cualquier idioma).
- La creación automática de rama está controlada por `AutoCreateBranch` en `specs/.spec-config.yml` (por defecto `true`).
- `/tesseract-bug` siempre trabaja en una rama propia (`fix-ocr-<slug>`) que ella misma crea tras confirmación explícita; nunca edita código en `master` ni `main`.

Cuando se implemente una feature de este proyecto, sigue este flujo en vez de escribir código directamente salvo que el usuario pida explícitamente saltarlo.

- `specs/18-sistema-plugins-nucleo.md` (`Aprobado`) — sistema de plugins: registro que descubre carpetas (`plugins_core/` para los tres motores esenciales, `plugins/` para terceros), valida su manifiesto (`model/plugin_manifest.py`), importa el módulo de forma aislada y despacha por capacidad (`model/plugin_registry.py`); `OcrController`/`LiveOcrController` dejan de conocer motores concretos y despachan vía `run_ocr`/`run_translation`, y los combos de motor OCR/traducción de `SettingsView` se alimentan del registro en vez de una lista fija.
- `specs/19-gestion-plugins-ui.md` (`Aprobado`) — vista "Plugins" (`view/plugins_view.py`, `controller/plugins_controller.py`) para ver, activar/desactivar, configurar y recargar los plugins instalados; generaliza en el manifiesto (`settings`, `PLUGIN_API_VERSION = 2`) los ajustes de un plugin, incluidos los campos obligatorios que antes resolvían a mano Tesseract y Claude, reemplazando esos dos chequeos hardcodeados por `missing_required_settings` + un diálogo genérico (`controller/common.prompt_missing_settings`); migra automáticamente `tesseract_path` y la API key legacy de Claude a sus ubicaciones nuevas en `config.json`/el keyring del SO.
